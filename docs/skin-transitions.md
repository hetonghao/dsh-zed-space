# 皮肤场景交接

已确认的视觉依据是 `bc19125` 中的 `preview/transition-prototype.html`。正式实现位于 `shared/skin-core.js`、`shared/cosmos.js` 与 `shared/ocean.js`，不依赖原型脚本或 `__bsState` 调试接口。

## 交接行为

海面与宇宙跨场景切换时，新场景在全尺寸但透明的 iframe 中准备最新配置。收到对应请求的首帧确认后，旧画面保持不透明并暂停，新画面在其上进行 550ms 透明度交叠。完成后立即移除旧 iframe，设置面板是否打开不影响释放。减少动态效果时采用 150ms。

同一宇宙场景的事件视界和吸积涡旋直接发送 `bs-skin`，保留原有约 2.2 秒视角插值，不进入通用交叠。`surface` 表示实际共享渲染器与原生切换能力，不是按题材随意分组。

本地视频使用独立的素材与播放通道。启用视频后释放内置场景；从视频切回内置皮肤时，暂停并保留视频画面，等目标首帧就绪后移除视频 iframe。未选中素材时使用海面回退。视频不参与上述 550ms 交叠。

反向切换从当前透明度继续；准备中的过期请求不能抢占最新选择。目标加载失败时恢复仍然保留的旧场景及其选择状态。首次启动宇宙失败则尝试海面。隐藏页面暂停双方绘制及合成动画，超时只计算页面可见时间。停用插件或销毁控制器时一并取消握手、动画与计时器。

## 首帧协议

宿主通过 `managed=1` 声明自行管理显现，此时渲染页面关闭自身的入场淡化并从暂停状态启动。

1. iframe 加载后，宿主发送 `bs-prepare`：严格递增的正安全整数 `requestId`、皮肤 ID、完整参数、昼夜开关和预览帧预算。
2. 子页面只接受指定父页的消息，应用最新请求并绘制一帧；初始化未完成时保留最新请求。
3. 经过两次动画帧回调后，子页面发送 `bs-frame-ready`，携带 `requestId` 和 `surface`，保持暂停。
4. 宿主检查来源窗口、来源域、已加载状态、场景类型和最新请求序号后才显现，并恢复目标场景。

`bs-surface-error` 报告渲染失败；既有宇宙 ready/error 协议保留供独立预览使用，但旧 ready 不触发正式交接。`bs-pause`、`bs-set`、`bs-preview` 继续承担原有控制职责。

新增独立渲染类型需登记宿主的场景入口并实现此协议；当前实测覆盖海面和宇宙两个渲染类型。新增类型仍需验证其首帧和多路快切，不应直接复用原型中的同源轮询。

## 验证

```sh
npm run check
npm run test:transitions
```

浏览器验收可用 `BACKSPACE_CHROME_BIN` 指定本机 Chromium 浏览器。测试覆盖首帧保留、同类旁路、反向快切、参数保留、来源校验、缩放、可见性、失败回退、停用清理和低帧预算恢复。产物写入 `.scratch/skin-transition/`。
