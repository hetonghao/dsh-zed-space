# 通用场景交接原型

临时原型分支：`codex/skin-transition-prototype`。基础提交：`9edde2823c6fda613c156a13662e0258e5ddc727`。

## 这版要回答的问题

550ms 的保帧交叠，能否自然连接明亮海面与黑洞，同时保持当前画质、完整参数与低常驻开销？已有场景内转场必须旁路：事件视界与吸积涡旋仍使用同一个画布及原有视角插值。

本轮只实现已经选定的一种视觉方向，便于判断真实转场。未新增三套布局或转场选项。代码与设置只作用于原型，不安装、不修改 dsh 桌面配置，不写入本地存储。

## 启动

在这个分支运行：

```sh
npm run preview:transition
```

打开终端输出的本地 URL。可附加 `?skin=ocean`、`?skin=horizon` 或 `?skin=vortex` 选择初始画面。复用仓库内的真实渲染资源，需要通过本地服务器访问。

## 体验顺序

1. 事件视界 → 吸积涡旋：状态显示“场景内动画”，保持一个宇宙场景，不做透明度转场。
2. 黑洞 → 海面 → 黑洞：目标首帧准备好后交叠；结束只驻留当前场景。
3. 在交叠中反向点击、连续选择：从当前混合程度续接，以最后选择为准。
4. 调节参数，再往返切换：宇宙八项参数和海面参数保持原值。
5. 点击“只看画面”观察；按 H 恢复控制。左右方向键切换皮肤，输入框调参时不拦截方向键。

## 实现边界

- 只在短暂交接期间保留两层全尺寸画面；旧场景暂停，新场景运行。
- 通用交叠默认 550ms，减少动态效果时 150ms。隐藏页面暂停渲染与交叠。
- 暂停按钮控制场景流动，选皮肤仍能完成交接到新的静帧。
- 同源原型通过现有 `__bsState` 识别首帧；正式接入时应替换为首帧握手协议。
- 只在原型 iframe 内关闭渲染页面自身的入场淡化，避免叠加两次动画；正式资源不改动。
- 目前保留两个实际渲染家族，用来验证通用交叠的视觉与交接逻辑。未来第三种家族需要接入正式生命周期协议，不把此原型直接当作生产引擎。

## 验收结论

浏览器验收记录保存在工作树 `.scratch/transition-prototype/`：7 项交互检查与 5 项生命周期检查通过，覆盖同类动画旁路、双向交叠、快切、八项参数保留、暂停调参重绘、冷启动期间修改目标、手机布局、减少动态效果、缓存导航路径及加载失败回退。已查看交叠中段与两端的真实截图。现有 28 项测试及生成资源一致性检查通过。

原型观感由用户预览确认；本轮不把未确认的设计推广到正式插件。未在 dsh 桌面内安装或测试，也未测量跨设备能耗；交叠期间调整窗口大小尚未做专项验收。
