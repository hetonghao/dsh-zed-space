# Spec: 多皮肤壁纸（内置代码皮肤 + 用户导入视频）

状态：已完成 02、03；01、05 部分完成；04 已实现待补跨路径验收；06 待原型后实施；07 等待发布。详见 `progress.md`。
取证基线：合并上游 `v1.2.6` 后的 `34f0c07`。

## Problem Statement

Backspace 现在只有一种背景：程序化的 WebGPU 海洋。可调、省体积、任意分辨率清晰，
但**画面内容被代码锁死**——用户喜欢星空、云海，只能等新着色器写出来。

而"换一种视觉氛围"是换肤插件最核心的诉求。用户手上可能就有一段很喜欢的视频，
却没有办法把它变成 Harness 的背景。

## Solution

背景抽象成**两类模式**：

| 模式 | 内容 | 素材 |
|---|---|---|
| **内置** | 代码驱动的程序化皮肤，多个可选 | 随包，纯代码，无媒体文件 |
| **视频** | 播放一段循环视频 | **不内置**，由用户导入 |

首版内置 **3 个皮肤**：现有`海面` + 2 个新增（都以 `cosmic-black-hole.mp4` 为参考做
代码驱动重建，一个忠实、一个同源再生）。

每个皮肤有**自己的独立配置项**；通用配置也按皮肤独立保存与重置，只有总开关全局生效。此约定按用户 2026-10-25 的最新决定更新。

## 当前实现与历史草案

海面与宇宙已采用独立入口，两个宇宙视角共享场景；后续认可的视觉效果与生命周期修复已替代原先的单入口、海洋源码冻结和参考片静止约束。下方量测保留为设计来源，不再作为已关闭票据的逐项实现要求。视频导入继续按 06 执行。

## 核心决策（含依据）

### 不做"逐帧分层逆推"

原始设想是"用开源工具把视频逐帧分割成层，再代码化"。**已评估并否决**，三条独立理由：

1. **信息上限**：遮挡区像素没有任何观测信息，只能靠内绘"编"；半透明介质
   `V = αF + (1-α)B` 是病态逆问题；单目深度是尺度不定的相对量。分层这一步的上限是
   "看起来合理"，不是"准确"。
2. **压缩比**：15s/1080p ≈ 2.8×10⁹ 个像素值 → 一个皮肤约 60 个参数，压缩比 ≈ 4.5×10⁷:1。
   这个量级下不存在"100%"。
3. **可验收性**：把分层结果当产物，等于分发用户素材的骨架化副本——不可审、含原始像素、
   体积不可控，许可上也无法落纸。

替代目标：**参数化重建 + 对齐参考帧**。验收用"行为/结构/主观/工程不变量"四层，
不用 PSNR/SSIM/LPIPS 当达标线（程序化重建与实拍在纹理统计上必然偏离，这类指标会稳定判负）。

### "逐帧"是错的单位

代码皮肤是时间连续、分辨率无关的。把 450 帧喂给 shader 等于又做了一遍视频管线。
正确单位是**关键态 + 周期函数**（3–5 个姿态）。

### 参考素材的量测结果（决定方案）

`cosmic-black-hole.mp4`：1920×1080 / 30fps / 25.07s / 752 帧 / 1.15 Mbps。

| 量 | 值 | 含义 |
|---|---|---|
| 黑洞盘 | 正圆，圆心 (0.500·W, 0.505·H)，半径 0.160·H | 正圆 ⇒ 无盘倾角 ⇒ **无引力透镜** |
| 亮度分位 | p50=0.039　p75=0.071　p95=0.269；>25% 仅占 5.4% | 四分之三近黑，容错极高 |
| 帧间变化（全幅） | 3.1s 内平均 \|Δ亮度\| = 0.45% | 几乎静止 |
| 分区帧间变化 | 盘 0.05%　星空 0.23%　星云 0.32%　细丝 0.95% | **只有细丝在动** |
| 星云频谱 | 25% 能量在 λ≈6–7px@960；低频块仅 8% | 高频丝状细节 ⇒ 域扭曲 FBM |
| 调色板 | `#010102` `#08080D` `#13121E` `#3E2941` `#A75B6E` `#F4AEAA` | 暗蓝紫底 + 玫红细丝 |

**结论：没有相机视差、没有透镜、97% 静态。** 因此不需要 3D 建模工具（Blender / Houdini /
EmberGen），也不需要深度/抠像/光流模型。一个全屏 pass 的域扭曲 FBM + 屏幕空间黑圆 + 一条
被噪声扰动的丝带即可。这部分算力预算远低于现有海面的 5 波 Gerstner + bloom。

### 内置视频不随包

用户明确选择：**视频模式不内置素材**。包内只允许代码与极小参数，禁止视频/帧序列。
好处：包体维持百 KB 级；无素材许可风险；无 MIME/Range/autoplay 的一整层问题。

### 用户导入素材的边界（已实测）

- 同源 iframe 可读宿主页的 `blob:` URL；**跨源抛 `SecurityError`**。
- 扩展路径的 iframe 是 `chrome-extension://` ⇒ **必须通过 `postMessage` 传 Blob**
  （结构化克隆，峰值内存 ≈ 2× 文件体积），不能传 URL 字符串。
- content script 与扩展 iframe **不同 origin，`IndexedDB` 不共享**。
  素材必须由 **iframe 自己持有的存储**保存，控制器只投递一次。
- `chrome.storage.sync` 单条 8KB，且开启同步时会上传到用户 Google 账号 ⇒ **素材绝不进设置存储**。
- 设置存储的适配器对非布尔键一律 `Number(value)` ⇒ **新增字符串枚举字段会被静默吃掉**。

### 不做运行时转码

已实测：转码耗时约 1× 实时（8.09s 处理 7.98s 素材），是成本不是优化；重编码必然有损；
用户素材不进包，转码对包体积零影响；本地 `VideoEncoder` 不支持 `avc1`。

改为**导入前预检**：只读元数据（毫秒级，不解码），不合格则说明原因并给出改法。

### 入口分派

入口页当前硬编码加载海洋渲染器。改为**按皮肤 id 分派**，且**失败一律回退到海面**——
`shared/ocean.js` 保持字节不变（它被 3 条字节等同断言冻结），新皮肤放在新文件里。

## Architecture（历史草案，当前实现以下方进度记录为准）

```
shared/skin-core.js          控制器：面板 DOM / 存储 / iframe 挂载（既有，改）
   └─ 通过 options.assetUrl + options.storage 与宿主解耦（既有契约，不扩）
shared/skin-boot.js          新增：读 ?skin=<id> → import()；失败 fallback → ./ocean.js?skin=1
shared/skins/index.js        新增：唯一注册点，Object.freeze 字面量
shared/skins/<id>.js         新增：每皮肤一文件，复用 ocean.js 的 SECTION 而不是复制
shared/ocean.js              不改（637 行，SECTION 1–9）
extension/skin.html          改 1 行：改为加载 skin-boot.js
```

三条安装路径仍由 `scripts/build-runtime.mjs` + `build-dsh-bundle.mjs` 从同一份源码生成。
**资产白名单有 6 处手写**（`build-runtime.mjs` emit、`manifest.json` WAR、
`install-skin.sh`、`package.json files[]`、`build-pages.mjs`、`static.test.mjs` 目标数组），
漏一处即对应路径静默 404 ⇒ 必须加"三路径产物集合相等"的断言。

## Testing Decisions

只验证外部可观察行为：画面、面板状态、持久化结果、"失败时会不会白屏"。

**优先测三件"会真坏"的事**：

1. 任何皮肤加载失败 ⇒ **回退海面，不白屏**。底线，必须自动化。
2. 设置**真的被持久化** ⇒ 三条路径各验一次（配置漂移已真实发生过两次）。
3. 新皮肤产物在三条路径下**都能加载** ⇒ 6 处白名单最容易漏。

**复用现有接缝**：`tests/static.test.mjs`（构建一致性）、
`scripts/desktop-acceptance.mjs` / `official-desktop-acceptance.mjs`（真浏览器）、
fixture 服务（`scripts/browser-support.mjs`）。

**不做**：像素级画质比对、转码测试、视频编码质量、逐帧分层正确性（无 ground truth）。

## Out of Scope

- 运行时转码 / 格式转换
- 素材编辑（裁剪、调色、变速）
- 多视频播放列表 / 随机轮播
- 在线视频源 / 流媒体 URL（破坏"零网络请求"承诺）
- 内置视频素材（用户已明确不内置）
- 配置架构重构（把 6 处手写清单收敛成单一 schema）——独立议题
- `harness-plugin/` 源码注入路径（与 npm 路径互斥，已存在字段漂移）
- 插件市场提审流程本身
